# Восстановление исходных меток МРТ Атласа

Проверено 18 октября 2026, сборка 1.25. Этот файл и `tools/` являются сохраняемой инструкцией для следующих сессий. Не полагаться на память диалога.

## Какие файлы использовать

- Актуальная основа интерфейса: пользовательский `MRIAtlas-1.23-anatomy-sections.apk`. Его assets перенесены в проект перед правками.
- Данные: `net.imaios.eanatomy.zip` из пользовательского архива.
- Внутри ZIP: `net.imaios.eanatomy.ab`, Android Backup версии 1, zlib, без шифрования контейнера.
- Нужный APK расположен ВНУТРИ резервной копии: `apps/net.imaios.eanatomy/a/base.apk`. Не подменять его отдельным защищённым APK e-Anatomy 6.0.4.
- База: `apps/net.imaios.eanatomy/db/eAnatomy.db`.
- Архивы изображений: `apps/net.imaios.eanatomy/ef/v5/.files/{module}.zip`.
- Аккаунты, пользовательскую БД и настройки извлекать не требуется.

## Повторяемая процедура

Из корня проекта, Python 3.10+:

```sh
python -m pip install androguard sqlcipher3-binary pillow
python tools/recover_source_database.py /path/net.imaios.eanatomy.zip /tmp/atlas-source-new
python tools/import_source_modules.py /tmp/atlas-source-new app/src/main/assets --report review/source-import-new.json
```

Используйте новый каталог для восстановления. Скрипт не перезаписывает открытую базу. Скрипт импорта рассчитан на имеющиеся модули и проверяет полное совпадение множества исходных изображений с текущим приложением, включая повторения.

После четырёх строк заголовка AB следует zlib-поток TAR. Стандартный tarfile отвергает контрольную сумму некоторых заголовков этого архива. Восстановитель читает блоки по 512 байт, проверяет размеры и извлекает исключительно точный белый список имён в фиксированные локальные файлы. Это не универсальный распаковщик повреждённых архивов.

## Как открывается база

Это SQLCipher, совместимость **3**. Обычный sqlite3 до экспорта не подходит.
В `classes.dex` вложенного APK статическая строка находится в классе `Leanatomy/library/a/a;`, метод `b`, дескриптор `()Ljava/lang/String;`, инструкция `const-string`.
Алгоритм: Base64 → UTF-8 → XOR 128 каждого символа → обратный порядок символов.
Результат используется только во время выполнения как ключ SQLCipher; не печатать его и не сохранять в проекте.
Порядок подключения: `PRAGMA key`, затем `PRAGMA cipher_compatibility=3`, проверка `sqlite_master`, затем `ATTACH ... KEY ''` и `sqlcipher_export`.
Конкретные класс и метод относятся к этой версии вложенного APK; при смене версии скрипт должен остановиться, а не угадывать ключ.

## Привязка кадров и точек

1. `module.imaios_code` выбирает модуль.
2. `series.module_id` задаёт серии, `sort_order` — порядок. `contrast.series_id` задаёт контрасты. При отсутствии записей использовать `contraste_`.
3. `slice.series_id` задаёт кадры. Число в имени файла — **slice.sort_order**, глобальный номер внутри модуля, не индекс списка с нуля.
4. Имя JPEG в ZIP без расширения:
   `SHA256("{module}#{contrast.imaios_code}#images-{slice.sort_order:04}.jpg")`.
5. Имя цветной PNG-маски:
   `SHA256("{module}#{filter.layer}#images-{slice.sort_order:04}.png")`.
6. `point.slice_id → slice._id`; `point.structure_id → structure._id → structure.name_id`.
7. Перевод: `translation.imaios_key = name_id`, `lang_id=10` — русский, резервный `lang_id=2` — английский.
8. Координаты `x_pixel,y_pixel` относятся к исходному изображению. Не делить их на `series.canvas_width/height`: эти поля не совпадают с размерами JPEG. Размеры читать из JPEG; текущие ЛЗС/локоть 640×670, таз 641×671.
9. Группы: `filter.module_id`, иерархия `parent_id`, показ `default_active`, цветные слои `layer`. Значок: `filter.icon_id → icon.name → assets/cats/{name}.png` во вложенном APK.
10. В манифест сохранять sourceSeries, sourceFrame, annotation, original, SHA256 содержимого, width, height. Не размещать одну фиксированную точку на произвольном диапазоне срезов.

## Что нельзя потерять при следующем импорте

`brain-data.json` и `brain-labels.json` из пользовательского APK оставлены побайтно неизменными. В brain-labels уже есть ручные правки ВСА, признаки approximate, примечания и поиск. Повторный импорт сырой базы поверх мозга уничтожит эти изменения. Скрипт новых модулей мозг не изменяет.

Новые модули используют `source-mri-viewer.js` и общий AnnotationLayer. Подписи остаются в координатах экрана при увеличении; изображение и маски обновляются после загрузки совместно. Настройки групп хранятся отдельно для каждой области. Связь окон разрешена только для одной sourceSeries, не по относительному положению разных плоскостей.

## Подпись Android

Ключ загруженного APK 1.23: SHA256 сертификата `accab9036c57b34689f7ac89dc8492ddb4857558a0b92c0c0aa790c2a559b623`.
Сохранившийся ключ из проекта 1.18: `9cc66233387f434c95059fc032f12bf3fbed77345bca5d976e32e45b877cec14`.
Они различаются, поэтому новую сборку нельзя выдавать за обновление поверх установленной 1.23.
Сборка 1.25 имеет отдельный applicationId `ru.grigory.shoulderatlas.restored`, имя «МРТ Атлас · метки» и устанавливается рядом. Старый атлас удалять не нужно. Настройки в новой установке начинаются заново.
`build-apk.sh` требует существующий ключ в SIGNING_DIR; автоматическая генерация замены запрещена. Сохранённый ключ сборки приложен внутри `release-signing/atlas.jks` исходного проекта; локальная учебная сборка, alias/password: atlas/android. Не публиковать ключ в открытом репозитории.

```sh
ANDROID_SDK_ROOT=/path/android-sdk SIGNING_DIR="$PWD/release-signing" bash build-apk.sh
```

Скрипт использует Android API 35/build-tools 35.0.0, Java 17; minSdk 26. Испытания на физическом телефоне не выполнены: проверены данные, логика интерфейса, APK и подпись.
