# Сохранение MRIAtlas без повторной загрузки проекта

Текущее подтверждённое состояние: START-HERE.md. Версию брать из app/build.gradle, а не из старого описания сборки.

## Один набор изменений — один коммит

При доступной локальной Git-аутентификации из корня checkout:

```sh
python3 tools/push_changes.py --message "Описание законченного изменения" app/src/main/assets/changed-file.html START-HERE.md
```

Указывать реальные изменённые пути. Скрипт не включает остальные файлы, не принимает уже заполненный index, проверяет main и расхождение с origin/main, отправляет один push без force. --commit-only сохраняет локальный коммит без сети. При конфликте не повторять отправку вслепую: получить новый head и согласовать изменения. APK, ключи и build-выходы блокируются; файлы при отказе сохраняются.

Если локальный Git недоступен, небольшие текстовые изменения сохранять одним GitHub tree/commit на основе текущего дерева, затем двигать main с expected_sha. Это сохраняет неизменённые blobs и уменьшает число запросов. Не создавать отдельный коммит для каждого файла. Не выводить полный ответ API, большой diff или base64 изображений в обсуждение.

## Сборка и публикация

Build Android APK — ручная проверочная сборка без подписи. Publish current signed MRIAtlas — ручная сборка с прежней подписью, проверкой package/версии/ZIP/assets и обратным скачиванием опубликованного APK. workflows уже существуют; не добавлять push-триггеры для каждого коммита. APK размещать в Releases, а не в исходном git-дереве. Не объявлять успех до проверки результата workflow.

Снимки и исходные архивы не перезаливать без изменения. Ключ восстанавливать по SIGNING.md, новый не создавать. Не удалять историю, архивы восстановления и резервные релизы ради лимита чата.
